# 架构

## 一句话

一个无界面的**动作核心**，外面挂三张皮（GUI / CLI / MCP）。皮是可换的，核心只有一份。

## 全景

```
                         ┌───────────────────────────────────────┐
   双击 / 文件关联 ──────▶│  redline.exe (GUI 子系统，单二进制)     │
   redline inspect a.docx│  main.rs 按第一个参数分流               │
                         └──────────┬────────────────┬───────────┘
                                    │ 无子命令        │ 有子命令
                                    ▼                ▼
                         ┌──────────────────┐  ┌──────────────┐
                         │ Tauri 壳 (GUI)    │  │ redline_cli  │
                         │ 三栏工作台         │  │ ::run()      │
                         └────────┬─────────┘  └──────┬───────┘
                                  │ redline_call      │
                                  ▼                   ▼
                    ┌─────────────────────────────────────────┐
                    │   redline_core::dispatch(id, params)     │  ★ 唯一实现
                    │   ──────────────────────────────────     │
                    │   format / inspect / diff / apply        │
                    │   archive / agent                        │
                    └─────────────────────────────────────────┘
                                  ▲
                                  │ （待实现）
                         ┌────────┴─────────┐
                         │  redline-mcp     │◀── 外部 agent 直接调
                         └──────────────────┘
```

## 为什么这么分

### 核心是 Rust，且无界面

- **无界面**：核心不知道自己被谁调用。它不打印、不弹窗、不读环境变量做界面判断，
  只接受参数、返回信封。这是它能同时服务三张皮的前提。
- **Rust**：要发单 exe、要做文件关联、要在客户机上跑而不预装 Python/Node。
  之前的 Python CLI 需要目标机器装 Python，那在装机场景是硬伤。

### 三张皮各自的职责边界

| | 干什么 | **不许**干什么 |
|---|---|---|
| GUI | 渲染、承载标注、展示结果 | 判扩展名、算 diff、决定能不能覆盖文件 |
| CLI | argv → params，打印信封 | 任何业务判断 |
| MCP | tool schema → params | 同上 |

判断标准很简单：**换一张皮，这段逻辑要不要重写？**
要重写的（读文件字节、存标注、开文件选择器）是宿主能力，留在皮里；
不用重写的（怎么解析 docx、什么算不安全路径）是业务动作，必须在核心。

## 数据流：一次完整的「标注 → 改 → 对照」

```
1. 用户打开文件
   GUI ──redline_call("document.inspect")──▶ core
                                             ├─ format::detect  按扩展名定格式
                                             ├─ ooxml::Parts    解 zip + XML
                                             └─ 产出 Snapshot { units: [{id,label,text}] }
   GUI 拿 units 画 unit 切换器；viewer 单独读 bytes 渲染像素

2. 用户在左栏圈选
   AnnotationLayer 产出 RedlineAnnotation { unitId, kind, bbox(分数坐标), note }
   RedlinePanel 通过 onAnnotationsChange 上抛给 App
   标注存进宿主的 kv（Tauri 侧是 app data 下的 annotations.json，原子写）

3. 用户在中栏选 agent、点派发
   GUI ──redline_call("agent.dispatch", {agent, source, output, annotations})──▶ core
                                             ├─ enrich()      从快照给每条标注补上 unit 正文
                                             ├─ build_prompt() 拼成工单（含「不许改源文件」硬约束）
                                             ├─ resolve_program() PATH 里解析出完整可执行路径
                                             └─ spawn + 提示词写 stdin + 超时 + 收 stdout/stderr
   返回 DispatchReport { command, prompt, exitCode, outputExists, ... }

4. 右栏对照
   outputExists 为真才继续：
   GUI ──redline_call("document.diff", {before: source, after: output})──▶ core
   同时把 RedlinePanel 开在 output 路径上（readOnly，不画标注层）

5. 不满意 → 回到 2，继续加标注再派一次。源文件全程一个字节没动。
```

**关键设计点**：标注只上报 `{unitId, note}`，unit 正文由核心从快照补。
界面不重复读文档——不然「AI 看到的内容」和「人看到的内容」会是两次独立解析的结果，
迟早对不上。

## 两个「注册表」和它们的关系

| | 位置 | 地位 |
|---|---|---|
| 权威格式表 | `crates/redline-core/src/format.rs` | **单一真相源**。扩展名映射、能力、viewer 绑定、拒绝理由 |
| 渲染层格式表 | `packages/redline-core/src/viewers/registry.ts` | 它的投影。只保留「懒加载哪个组件」 |

为什么不干脆运行时从核心拉：viewer 走 `React.lazy` 静态 import，打包器要在构建期
看得见路径才能分包。所以表结构留在 TS，一致性交给 `scripts/check-format-parity.mjs`
（改任一边都要跑，漂了就退出码 1）。

**新增一个格式的完整步骤**：

1. `format.rs` 的 `FORMATS` 加一条（扩展名、能力、viewer 名）
2. `inspect.rs` 的 match 加分支（如果声明了 `inspect: true`）
3. `packages/redline-core/src/viewers/` 加 viewer 组件
4. `registry.ts` 的 `EXT_TO_FORMAT`、`FORMAT_TIERS`、`LOADERS` 各加一条
5. `document-model.ts` 的 `RedlineFormat` union 加一项
6. 跑 `node scripts/check-format-parity.mjs` 确认没漂

## 单 exe 是怎么做到的

`apps/redline-desktop/src-tauri/src/main.rs`：

```
第一个参数 ∈ SUBCOMMANDS  →  attach_parent_console() → redline_cli::run() → exit(码)
否则                       →  redline_desktop_lib::run(第一个参数当待打开文件)
```

- exe 是 **GUI 子系统**（`windows_subsystem = "windows"`），双击不闪控制台
- 代价是从命令行调用时标准句柄可能没继承，所以 CLI 分支要 `AttachConsole`，
  且**只补空句柄、不覆盖已有的**（覆盖会把重定向冲掉）
- `redline-cli.exe`（console 子系统）同时构建，给需要严格控制台语义的场景

## 宿主适配层（TS）

`RedlineHost` 接口是 `packages/redline-core` 能被任意宿主复用的原因：

```ts
interface RedlineHost {
  readFileBytes(path): Promise<ArrayBuffer>   // 必需
  annotationStore: { get, set }                // 必需
  sendToAgent?(text)                           // 可选
  openExternal?(path)                          // 可选
  getSrcUrl?(path)                             // 可选，省一次内存拷贝
}
```

已有两个实现：本仓库的 `apps/redline-desktop/src/host.ts`（Tauri），
以及 OpenCodex 仓库的 `src/opencodex/redline-host-tauri.ts`。

**改这个接口要同时改两处宿主**，且 OpenCodex 那边还有一份 vendored 副本要同步。

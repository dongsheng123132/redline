## P0 — 文件关联 + 右键菜单

**目标**：装完之后双击 `.zip` / `.pdf` / `.docx` 直接用 Redline 打开；
右键菜单有「用 Redline 打开」和「解压到当前文件夹」。

**为什么是 P0**：这是从「一个能跑的 exe」到「每台电脑都有」之间**唯一的硬障碍**。
WinRAR 的全部粘性来自于此——装完你根本不会想起它，但每天在用。
整个商业模型（见 `docs/商业模型.md`）都压在装机量上，而装机量压在这一步上。

单 exe 那一半已经做完了：`redline C:\包.zip` 已经能直接打开。差的是注册表那一步。

**怎么算做完**

- [ ] NSIS 安装脚本注册 `HKCU\Software\Classes\Redline.<ext>` + `OpenWithProgids`
- [ ] 安装时**让用户勾选**要关联哪些扩展名，默认只勾 `.zip` `.7z` `.rar`
      （别默认抢 `.pdf` `.docx`——那是最招人恨的行为）
- [ ] 右键菜单：`用 Redline 打开` / `解压到此处` / `解压到 <文件夹名>\`
- [ ] **卸载时干净还原**原来的关联，不留残骸
- [ ] 干净机验证：装 → 双击 zip 打开 → 卸载 → 双击 zip 回到原来的程序

**边界**

- 不碰 `HKLM`（要管理员权限，且会影响所有用户）
- 不做「默认程序抢占」那套流氓行为，Windows 10+ 也不允许静默改默认
- 不做托盘常驻（这一版不需要，且常驻会被杀软盯上）

**适合谁做**：注册表脚本和 NSIS 模板机械但琐碎，**适合丢给 codex**；
「关联哪些、默认勾什么」这个决定要人拍板。

## P0.5 — 可信发布链

**目标**：用户从官网、GitHub、WinGet 或 Microsoft Store 拿到的都是同一个可验证版本；
安装、更新、卸载都不会制造杀软恐慌或留下文件关联残骸。

**为什么紧跟 P0**：文件关联需要安装器取得用户信任。没有签名、校验和干净卸载，
传播越快，负面口碑和 Defender 误报扩散得越快。

**怎么算做完**

- [ ] 发布的 exe、NSIS 安装包和更新清单使用可信代码签名
- [ ] GitHub Release 附 sha256、变更记录、便携版和安装版
- [ ] 建立可回滚的更新清单；客户端不接受降级或未签名清单
- [ ] Windows 沙箱验证静默安装、正常安装、覆盖升级、卸载和关联还原
- [ ] 安装链稳定后提交 WinGet；Microsoft Store 放到公开 Beta 后
- [ ] 诊断包默认不含路径、文件名、正文、标注和提示词

**边界**

- 不做静默强制更新
- 不使用自签名证书冒充正式签名
- 不为了装机量捆绑进 U-Claw/U-King；必须由用户明确选择

## P1 — rar / 7z 解包后端

**目标**：`archive.list` / `archive.extract` 支持 rar / 7z / tar / gz / xz / iso / cab。

**为什么**：不支持 rar，「替代 WinRAR」就是假的。格式表已经认了这些扩展名并给出
正确提示（`extract_backend_missing`），差的是后端。

**怎么做**：**进程外调用 7z 可执行文件**。这是 license 决定，不是技术偏好——
7-Zip 里的 RAR 解压代码用的是 unRAR license（禁止用于重建 RAR 压缩器），
只有进程外调用才不把它拖进我们的二进制。跟本项目处理 LibreOffice 的老办法一致。

**怎么算做完**

- [ ] `format.rs` 的 `ExtractBackend::External7z` 分支接上真实实现
- [ ] 按顺序找 7z：环境变量 `REDLINE_7Z` → PATH → 常见安装路径 → **随包附带的 7za.exe**
- [ ] 找不到时报的错要能直接念给用户听（现有 `extract_backend_missing` 文案已经写好）
- [ ] **zip-slip 防护对 7z 输出同样生效**：不能因为换了后端就绕过 `safe_relative_path`
      （7z 自己有 `-snld` 之类选项，但别依赖它——在我们这一侧再验一遍）
- [ ] 加密压缩包：识别出来并明确报「需要密码」，不要静默失败
- [ ] 测试覆盖：正常 rar、带中文名的 rar、zip-slip 恶意 rar、加密 rar

**边界**

- 不自己实现 RAR 解压算法（license 雷区）
- 不做**压缩**功能。这一版只解不压——压缩是另一个产品面，先把「打开」做到最好

**适合谁做**：codex 能做大部分，但 **license 那条约束要在 prompt 里写死**，
否则它很可能顺手 `cargo add unrar`。

## P1.5 — ShadowDoc + 重点格式 10 倍体验

**目标**：不是只增加扩展名数量，而是把 PDF、DOCX、XLSX、PPTX 四个高频格式做到
「首屏快、位置准、AI 上下文少、结果好对照」。完整模型见 `docs/影文档协议.md`。

**为什么在 MCP 前**：MCP 会放大核心提供的能力。如果人看到的视觉 unit 与 AI 读取的
语义 unit 还会漂，越早暴露给外部 Agent，兼容债越大。

**已经完成的最小基础**

- [x] `document.inspect` 输出 `redline.shadow-document` v1 描述
- [x] 每个 unit 有稳定 `kind` 和 `textSha256`
- [x] ShadowDoc 显式绑定源文件 sha256
- [x] PDF/XLSX/PPTX viewer unit ID 与 Rust 核心统一
- [x] Tauri 预览优先消费核心语义 units，视觉首屏不等待 inspect
- [x] 标注存储按路径 + 源哈希隔离
- [x] `agent.dispatch` 支持 `expectedSourceSha256`，源文件变化时报 `stale_shadow`
- [x] ShadowDoc Core 0.1 normative spec + JSON Schema
- [x] 无第三方依赖 validator + valid/invalid conformance fixtures
- [x] 可重复基准：锚点稳定、局部上下文、解析耗时、stale-source 拒绝
- [x] 第一轮实验报告，明确记录真实 Markdown 单 unit 的 0% 收益反例
- [x] 文本/Markdown 确定性分块，核心与 TextViewer 共用同一批 `document:N` units
- [x] Markdown 反例复测：局部上下文从 0% 提升到 98.37%，锚点稳定率保持 100%
- [x] 隔离 Parser PK runner：Redline / MarkItDown / Docling，同源、重复、可跳过、机器报告
- [x] Redline vs MarkItDown 0.1.7 四格式受控 PK；两者召回与输出确定性均为 100%
- [ ] 在网络/缓存条件合适的机器补跑 Docling；本机 900 秒安装上限内未完成，不记失败

**下一步验收**

- [ ] ShadowBundle manifest：同一版本可挂 visual / semantic / conversion / OCR /
  AI-context / annotation 等多个 Layer revision
- [ ] Layer 明确区分 `source-derived`、`machine-inferred`、`human-authored`，
  OCR/AI 推断不能静默混入原件事实
- [ ] PDF：第一页渐进首屏、页面虚拟化、文字层按页缓存
- [ ] DOCX：段落 units 与 DOM 节点绑定，标注不再只覆盖全文单画布
- [ ] XLSX：按 sheet 延迟解码、行列虚拟化，去掉固定 500 行体验上限
- [ ] PPTX：外部转换出逐页视觉影子，同时保留文字语义影子
- [ ] ShadowDoc 缓存键包含源哈希、解析器/版本、schema 版本和 profile
- [ ] 工单默认只发送选中 units + 必要上下文，并记录相对全文的 token 节省
- [ ] 用同一份 50 页文档对比传统聊天流程，测总耗时、交互轮数、token 和错误修改数

**传统格式适配**

- [ ] 设计进程外 `ParserAdapter` 协议：输入原件，输出标准临时文件 + ShadowDoc
- [ ] `.doc/.xls/.ppt/.rtf/.odt/.ods/.odp` 走 LibreOffice/Pandoc 等转换预览
- [ ] UI 必须标「转换预览」和已知丢失风险，不把大纲或乱码冒充高保真
- [ ] 原格式继续被核心直接解析拒绝；只有显式转换动作能产生新副本

**边界**

- 不发明替代 Office/PDF 的主文件格式
- 不让通用 AST 直接无损写回所有格式
- 不为了格式数量牺牲首屏、稳定性和诚实的能力声明
- 外部适配器必须进程外、可超时、可取消、临时目录可清理

## P2 — redline-mcp

**目标**：把同一个 `dispatch` 包成 MCP Server，让外部 agent（不经过任何界面）直接调。

**为什么**：这是「成为 AI 操作文档的事实标准协议」那条线的载体。
成本很低——核心已经是 `dispatch(id, params) → 信封` 这个形状，MCP 只是第三张皮。

**怎么算做完**

- [ ] 先固化 `WorkOrder`，增加 `workorder.create / verify / export` 核心动作
- [ ] `agent.dispatch` 消费同一份 WorkOrder，不保留第二套提示词/安全约束
- [ ] `crates/redline-mcp`，stdio transport
- [ ] 每个 Action 映射成一个 MCP tool，schema 从契约文档生成或手写但**必须一致**
- [ ] `redline mcp` 作为单 exe 的一个子命令启动（加进 `SUBCOMMANDS`）
- [ ] 在 Claude Code 和 Codex 里各实测一遍：能 inspect、能 diff、能 apply

**边界**

- **不要在 MCP 层加任何业务逻辑**。它和 CLI 一样是薄壳。
  如果发现某个 tool 需要「先 inspect 再算一下」，那个「算一下」应该是核心的新 Action。
- 不暴露 `agent.dispatch` 给 MCP（agent 调 agent 容易套娃失控），先只暴露只读动作 + apply

## P3 — 版本图 + 无限画布

**目标**：把三栏的「一次修改回合」升级成 README 里描述的版本图：
横向连续修改、纵向从同一父版本分叉、画布可平移缩放、每个节点不可变、每条连线可审计。

**为什么在 P3**：这是产品差异化的大招，但它**依赖前面三项**——
没有装机量（P0）和格式覆盖（P1），版本图是给不存在的用户做的功能。
README 也明确写了「第一阶段仍用当前三栏把单次回合做扎实」。

**动作先行**：草案在 `docs/动作契约.md` 末尾（`version.create` / `list` / `get` / `branch` / `adopt`）。
**先把这几个 Action 在核心里做出来并有测试，再动画布 UI。**
反过来做的话，画布状态会变成第二份真相源，然后 CLI 和 MCP 永远追不上。

**怎么算做完**

- [ ] 核心：Shadow Project 目录 + manifest，绑定节点、Bundle、标注、WorkOrder 和 ActionEdge
- [ ] 核心：版本节点存储（内容哈希 + 父指针 + 分支名 + 那次 AI 动作的完整记录）
- [ ] 核心：`version.*` 五个动作 + 测试（尤其「分叉不是回滚覆盖」这条要有测试守）
- [ ] CLI：`redline version list / branch / adopt` —— 无界面也能操作版本图
- [ ] GUI：画布替换掉固定三栏，AI 动作卡可折叠/拖动/左收
- [ ] `version.adopt` 的「替换源文件」必须**显式二次确认**，且先留底

**边界**

- 版本节点不可变。任何「就地改一下上个版本」的实现都是错的
- 每个版本节点拥有自己的 ShadowBundle；可重建 Layer 可以清缓存，人的标注和动作历史不能丢
- `.shadowdoc` 若实现，只是项目 sidecar/container，不取代 PDF/Office 标准文件
- 不做多人协同（那是 v3+ 的事，会把数据模型复杂度翻好几倍）
- 画布不要自己造轮子；优先评估 MIT 的 xyflow。tldraw 当前 SDK 生产使用是专用许可，
  只有部分 starter kits 是 MIT，引入前必须复核当期条款和商业成本

## P4 — 一键 AI（虾盘云计费）

**目标**：没装任何 CLI 的用户也能用 AI 改文档，走虾盘云计量。

**为什么在 P4**：收入这一层，但**必须等装机量起来**。现在接等于给零个用户做收银台。

**怎么做**：在 `agent.rs` 的 `AGENTS` 表里加一条「Redline 云端」，
它不 spawn 本地进程而是走 HTTP。注意架构上这是**同一个 Action**（`agent.dispatch`），
只是多一个 agent spec——不要为它新开一套动作。

**怎么算做完**

- [ ] `AgentSpec` 抽象成 enum：本地进程 / 远程 HTTP，两条路径共用同一份工单拼装
- [ ] API key 只在服务端校验；客户端当成可被反编译（宪法第 11 条）
- [ ] 余额不足、限流、超时各自有明确文案，不要笼统报「失败」
- [ ] 用量在派发结果里如实回显（用了多少 token / 花了多少），**不要藏**

**边界**

- **免费层（打开 / 解压 / 标注 / 自带 key 派发）永远不设次数限制。**
  解压是水电，一收费用户立刻换回 7-Zip
- 不做捆绑安装、不做导航页、不做 nag 弹窗——国内压缩软件品类就是这么死的

## P5 — 企业版

**目标**：私有部署（不出网）、审计日志、统一策略、批量处理、SSO。

**为什么最后**：没有装机量的企业版卖不动。但底子已经在了——
`apply` 输出的审计记录（输入/输出 sha256、作者、逐条改动、回滚说明）就是合规凭证，
版本图的每条连线也是。

**边界**：企业侧的审计服务端 / 策略管理**另开私有仓**。
`redline-core` / CLI / MCP 保持 Apache-2.0，理由见 `docs/商业模型.md`。

## 1. 品牌与品类

### 工作品牌

| 层级 | 当前用法 | 说明 |
|---|---|---|
| 中文品牌 | **叠象** | 「叠」是版本层叠与迭代；「象」是图像、表象、万象，不限定为大象 |
| 英文工作品牌 | **Stelora** | 待商标、公司名和域名正式检索；通过前不做全仓改名 |
| 中文品类 | **万能文件工作台** | 对外主品类，不用「AI 文件预览器」把产品说窄 |
| 英文品类 | **Universal File Workspace** | 比 viewer 更能容纳标注、修改、对照和版本分叉 |
| 当前代码名 | **Redline** | crate、Action ID、CLI 和仓库名暂不改 |
| 功能名 | **Redline Mode** | 将来可专指圈选、批注和逐处修订模式 |

推荐的完整写法：

> **叠象 Stelora · 万能文件工作台**
>
> Open anything. Mark anything. Let any AI revise it.
>
> 打开一切，标注一切，交给任意 AI 修改。

在完成第 9/42 类商标、近似商号和域名核验前，`叠象`、`Stelora` 都只是工作品牌。
不要因此改 crate 名、协议字段、安装包标识和更新地址。品牌确定后单独立项迁移，兼容旧 Action ID。

### Logo 原则

- 用三张向右错位的页面、窗口或图层表达「原件 → 标注 → 新版本」；
- 可以让负形组成抽象的「象」或分叉路径，但不画写实大象；
- 避免大象侧面、折耳轮廓和绿色/灰色大象，降低与 Evernote 的混淆风险；
- 红色可以保留为操作色，但界面主体应中性，红色只代表标注、差异和当前路径。

## 2. 一句话产品

**叠象是 Windows 上的模型中立万能文件工作台：打开和预览多种文件，在原件上标注，把修改交给任意 AI，生成不可变的新版本并逐处对照。**

产品类比：

> WinRAR 的万能打开 + Git 的版本分叉 + AI Agent 的修改能力。

这三个部分缺一不可：

- 只有万能打开，是另一个查看器或压缩软件；
- 只有 AI 修改，是 Claude、ChatGPT、WPS 或 Copilot 的一个功能；
- 只有版本图，是面向文件的 Git 前端；
- 三者连在一起，才是新的系统级文件入口。

## 3. 用户真正雇它完成什么

用户不是为了「使用 AI」而来，而是在这些时刻需要叠象：

1. 收到一个电脑打不开的文件，不想先安装几百 MB 的原软件；
2. 文件能看，但不知道怎么准确告诉别人或 AI「改这里」；
3. AI 改完后，担心改错、改丢、覆盖原件，无法逐处确认；
4. 一个 AI 改得不好，想换另一个 AI，或回到旧版本尝试另一条路线；
5. 企业需要知道谁、在什么时候、让哪个模型、基于哪个原件做了哪些修改。

因此冷启动入口必须是：

> **文件打不开，先用叠象。**

AI 是打开之后自然发生的下一步，不是安装叠象的前提。

## 4. 不与 Claude/Codex 比谁更聪明

截至 2026-07，ChatGPT 桌面端已经支持文档、表格、演示和 PDF 的预览，
并能在部分预览中圈定区域继续修改；Claude 已能创建和编辑 Office/PDF 文件，
Artifacts 也支持版本切换与继续迭代：

- [OpenAI：Work with files](https://learn.chatgpt.com/docs/artifacts-viewer)
- [Anthropic：Create and edit files with Claude](https://www.anthropic.com/news/create-files)
- [Anthropic：Artifacts](https://support.anthropic.com/en/articles/9487310-what-are-artifacts-and-how-do-i-use-them)

所以「AI 会改文档」不是护城河。叠象必须把 Claude、Codex、Gemini、本地模型和垂直
Agent 都当成**可插拔发动机**。模型进步时，叠象随之变强，而不是被模型替代。

### 叠象负责的层

| 叠象长期负责 | 交给模型或外部工具 |
|---|---|
| Windows 双击、拖放、右键菜单和文件关联 | 内容理解、生成与创作 |
| 格式识别、稳定预览、结构抽取和安全解包 | 对具体格式执行复杂修改 |
| 分数坐标标注与机器可读工单 | 根据工单完成修改 |
| 源文件不可变、新版本落盘、内容哈希 | 选择具体模型能力 |
| 跨模型的版本图、差异、回放和审计 | 模型自身的推理过程 |
| 本地优先、权限策略、失败分类 | 云模型的训练与托管 |

一句工程判断标准：

> 如果换掉 Claude/Codex，这个能力仍必须存在，它就属于叠象核心。

## 5. 五条护城河

### 5.1 系统入口

默认打开、右键菜单、拖拽、最近文件和可靠卸载决定日常使用频率。入口建立后，
用户不需要记住叠象，但会不断使用它。

### 5.2 长尾格式与透明降级

大厂会优先做 docx、xlsx、pptx、pdf；叠象要覆盖压缩包、PSD、DXF、3D、邮件、
数据库、安装包、字体和文件夹等长尾对象。

「支持」不能只有一个布尔值，应公开分级：

- A：高保真预览 + 结构抽取 + 差异；
- B：可预览或结构化大纲；
- C：通过外部转换器安全转换后预览；
- D：元数据、文件树和交给原软件打开；
- 拒绝：明确说明原因和下一步，不用乱码伪装成功。

### 5.3 不可变版本图

每次 AI 动作生成新节点；横向是继续修改，纵向是从旧版本分叉。
节点记录内容哈希、父节点、标注、整体要求、Agent、模型、权限、输出和差异。
源文件不覆盖，历史不重写。

### 5.4 模型中立

用户可以自带 Claude/Codex，也可以用叠象云端或本地模型；同一分支中允许换 Agent。
适配器越多，模型厂商之间的竞争越能增强叠象的价值。

### 5.5 本地优先与可审计

打开、预览、标注、解压、版本存储默认可离线。必须出网的 AI 动作，在执行前展示
将发送什么、发给谁、授予什么权限；执行后记录模型、成本和产物哈希。

## 6. 目标用户与进入顺序

| 顺序 | 用户 | 高频痛点 | 首个成功时刻 |
|---|---|---|---|
| 1 | 普通 Windows 用户 | 文件打不开、压缩包不干净 | 双击后立即看见内容 |
| 2 | 开发者与 AI 重度用户 | Agent 不会稳定处理各种文件 | 自带 key 完成一次标注修改 |
| 3 | 设计、投标、合同、运营人员 | 修改沟通反复、版本散乱 | 左右对照后确认一个新版本 |
| 4 | 团队与企业 | 文件不能出网、过程不可审计 | 策略内完成并导出审计记录 |

不要一开始同时服务所有行业。公开测试先选择两个演示性最强的场景：

1. 「没有 Photoshop/AutoCAD/Office，也能先看内容」；
2. 「在合同/PPT 上指出哪里改，换两个 Agent 生成并比较两个方案」。

## 7. 产品原则

1. **打开层永久免费、免登录、无次数限制。**
2. **源文件永不静默覆盖。**
3. **安全拒绝是功能，不是假失败。**
4. **业务动作只在 `redline-core` 实现一次。**
5. **用户可带自己的 AI，不被云服务绑架。**
6. **格式能力如实分级，不宣传虚假的“100% 支持”。**
7. **不捆绑、不改首页、不驻留、不抢默认应用。**
8. **未经明确同意，不上传文件内容和文件名。**

## 8. 北极星指标与验证指标

北极星指标不是下载量，而是：

> **每周成功打开并完成一次有意义操作的活跃设备数。**

「有意义操作」包括预览、解包、导出标注工单、AI 派发、对照或分叉，不包括只启动空窗口。

| 环节 | 首要指标 | 第一阶段通过线 |
|---|---|---|
| 安装 | 安装成功率、卸载还原率 | 干净机 100% 可还原文件关联 |
| 打开 | 支持文件成功进入可用视图 | 测试语料成功率 ≥95%，失败都有明确原因 |
| 性能 | 本地文件首个可用画面 | 常见小文件 P50 <1 秒，P95 <3 秒 |
| 激活 | 安装后 24 小时内第二次打开 | 内测期 ≥30% |
| AI | 标注后成功生成新文件 | 已派发任务成功率 ≥80% |
| 安全 | 源文件意外改变、越界写入 | 0 |
| 留存 | 第 4 周仍有有效打开 | 内测期 ≥20% |
| 商业 | 云 AI 复购、企业试点 | 到阶段门槛再定义，不提前做虚假预测 |

这些是早期产品门槛，不是对外承诺。真实数据连续两轮达不到时，应调整产品或顺序，
不能靠换一套指标宣布成功。

## 9. 当前不做

- 不训练自己的基础模型；
- 不做完整 Office、Photoshop 或 AutoCAD 替代品；
- 不做多人实时协同；
- 不把全部格式都承诺为可编辑；
- 不先做企业管理后台；
- 不以广告、捆绑或导航页变现；
- 不在商标核验前大规模迁移品牌标识。

## 10. 需要尽快验证的假设

| 假设 | 最小实验 | 失败信号 |
|---|---|---|
| 「万能打开」比「AI 文档助手」更容易获客 | 两个落地页、同一流量做标题 A/B | AI 标题显著更低获客成本且留存不差 |
| 用户愿意把叠象设为常用打开入口 | 20 台干净机使用两周 | 多数用户只手动打开一次 |
| 标注能显著降低 Agent 沟通成本 | 同一文件对比纯提示词与标注工单 | 修改轮数和成功率没有改善 |
| 模型切换和分叉有真实价值 | 记录是否从旧版本重新派发 | 低于 5% 用户使用，且访谈无需求 |
| 云 AI 能付费 | 自带 key 用户旁提供透明计价试用 | 只用自带 key，便利性不足以付费 |

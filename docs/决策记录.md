# 决策记录

> 记「**为什么**」，不记「做了什么」（做了什么看 git log 和代码注释）。
>
> 接手的人如果想推翻某条，先读完这里的理由。理由不成立了就推翻并**在这里补一条**，
> 别默默改掉——那样下一个人还会再纠结一遍。

---

## 1. 动作核心用 Rust，不继续用 Python

**背景**：第一版 CLI 是 `bin/redline.py`，纯标准库解析 OOXML，能跑。

**决定**：迁到 Rust（`crates/redline-core`），Python 版标记废弃。

**理由**

- 要发**单 exe**、要做文件关联、要在客户机上跑而不预装 Python。Python 版在装机场景是硬伤
- Python CLI 和 TS 渲染层各自实现了一遍文档解析，本来就是要消灭的漂移
- 加上计划中的 MCP，会变成三份

**代价**：apply 的替换逻辑要重写——Rust 的 `regex` 不支持 lookahead，
Python 那个 `(?:(?!</w:r>).)*?` 写法搬不过来。改成手工扫 `w:r` 边界。
额外收获：`<w:rPr>` 也以 `<w:r` 开头，手工扫描时必须判断下一个字符，
这个坑正则版本其实一直藏着。

## 2. 单 exe，不是 GUI + CLI 两个 exe

**决定**：`redline.exe` 一个二进制，按第一个参数分流。GUI 子系统。

**理由**

- 要取代 WinRAR 就必须能被双击、进右键菜单、做文件关联 → 必须是 GUI 子系统
- 但同一个能力又得能被脚本和别的 AI 无界面调用
- 分成两个 exe 的话，用户装完看到两个图标，「哪个是哪个」永远解释不清

**代价（已知，不是 bug）**：在 cmd/PowerShell 里**交互式**敲 `redline agents`
看不到屏幕输出，因为 cmd 不等 GUI 子系统的进程。管道和重定向都正常。
需要严格控制台语义的场景用同时构建的 `redline-cli.exe`。

**试过但放弃的方案**：console 子系统 + 启动 GUI 时 `FreeConsole`——
双击会闪一下黑框，对一个「每台电脑都装」的工具来说不可接受。

---

## 3. 全部保持 Apache-2.0，不做闭源桌面端

**决定**：core / CLI / MCP / 桌面端全部 Apache-2.0。只有企业侧服务端另开私有仓。

**理由**：fork 出来的客户端唯一能剥掉的是付费 UI，而付费依赖服务端的 key。
剥掉付费 UI 的 fork 只等于回到「自带 key」层——那本来就免费。
闭源换不到保护，却换掉了「成为 AI 操作文档的事实标准协议」这个更大的目标。

详见 `docs/商业模型.md`。

---

## 4. Redline 从不写回源文件

**决定**：唯一写文件的动作只写**新文件**；agent 派发的工单里写死「不许改源文件」。

**理由**：这不只是安全，是**三栏/版本图能成立的前提**。
右栏不是「改过的原文」，是另一个文件——所以左右两栏其实是同一个预览组件开在两个路径上。
版本图同理：每个节点不可变，「继续改」是生成新版本而不是原地改。

破了这条，整个交互模型就塌了。

---

## 5. apply 只支持 docx

**决定**：`document.apply-track-changes` 只处理 `.docx`，其他格式直接拒绝。

**理由**：只有 Word 有**原生 Track Changes** 能承载修订痕迹，
最终由用户在 Word/WPS 里接受或拒绝。pptx/xlsx/pdf 没有对应机制。

自己发明一套「修订标记」的话，产出的文件在任何别的软件里都打不开，
等于把用户锁死在 Redline 里——那既不诚实也不好用。

**不要**为了「功能完整」给 pptx/xlsx 加 apply。需要改那些格式就走 agent 派发路线
（agent 直接产出新文件），那条路已经通了。

---

## 6. 替换点必须唯一命中，命中多次直接拒绝

**决定**：`ambiguous_replacement`，不猜。

**理由**：命中两次意味着核心得替用户决定改哪一个。猜错了用户不一定看得出来，
而文档改错的代价可能很大（合同、申报材料）。
让人把 patch 写精确，比让核心猜要好——报错信息里已经写明匹配了几次。

---

## 7. `expected_input_sha256` 是状态版本号，对不上就拒绝

**决定**：原件在出 patch 之后被改过，直接拒绝执行（`stale_patch`）。

**理由**：影核协议第 16 条——**「最后写入者获胜」不许当未声明的默认**。
AI 基于快照 A 生成的 patch，套到已经变成 A' 的文件上，产出的东西没人能解释。

---

## 8. zip-slip 直接拒绝整包，不做「尽力清洗」

**决定**：条目路径里有 `..` / 绝对路径 / 盘符，整包拒绝解包。

**理由**：清洗过的路径会让用户**以为解出来的东西在他以为的地方**。
恶意包本来就不该解，报错比悄悄换个位置安全得多。

**配套决定**：解包分两趟——先把全部条目验一遍再落盘。
单趟边验边写会留下半截产物，用户看目录里有东西会以为解包成功了。
（这个是实测发现的：恶意包里第一条正常文件已经写出去了。）

---

## 9. rar/7z 走进程外调用，不编进二进制

**决定**：`ExtractBackend::External7z`，调外部 7z 可执行文件。

**理由**：**license**。7-Zip 里的 RAR 解压代码用的是 unRAR license
（禁止用于重建 RAR 压缩算法）。进程外调用不把它拖进我们的二进制。
跟本项目处理 LibreOffice 的老办法一致。

**给接手 AI 的警告**：不要顺手 `cargo add unrar` 之类的 crate。

---

## 10. 老二进制格式（.doc/.xls/.ppt）明确拒绝

**决定**：`legacy_binary_format`，给出「请另存为新格式」的可读理由。

**理由**：老版是完全不同的二进制格式，当成新版解析只会得到乱码，
然后用户以为是 Redline 坏了。

**这条已经出过事**：TS 注册表当年把 `.doc` 映射到 `docx`，Python CLI 明确拒绝，
两边不一致了很久没人发现。现在 Rust 是唯一真相源 +
`scripts/check-format-parity.mjs` 守着。

---

## 11. 格式表：Rust 是真相源，TS 是投影

**决定**：权威表在 `crates/redline-core/src/format.rs`，
`packages/redline-core/src/viewers/registry.ts` 只保留「懒加载哪个组件」，
靠检查脚本守一致。

**为什么不干脆运行时从核心拉**：viewer 走 `React.lazy` 静态 import，
打包器要在构建期看得见路径才能分包。

**检查脚本必须能真的失败**——已经验证过：把 `.doc` 改回映射 `docx`，脚本立刻退出码 1。

## 12. 提示词走 stdin，不走命令行参数

**决定**：`agent.dispatch` 把工单写进子进程 stdin。

**理由**（Windows）

1. `codex` / `claude` 都是 npm 装的 `.cmd` shim，参数要过 cmd.exe 再解析一遍；
   提示词里的换行、`& | " ^` 会被吃掉或改写
2. Windows 命令行总长约 32KB，长文档的工单撑得爆

**配套**：必须先在 PATH 里解析出**完整可执行路径**（按 PATHEXT 试后缀）再 spawn。
`Command::new("codex")` 只会找 `codex.exe`，找不到 `codex.cmd`——
症状是「清单说已安装、派发说没装」，最误导人的那种错。

---

## 13. codex 派发加 `--skip-git-repo-check`

**决定**：加，并如实写进 `permissionNote`。

**理由**：codex 默认只肯在 git 仓库里跑（怕改坏没版本控制的东西）。
但文档不可能都放在 git 仓里，这条不放开 Redline 就没法用在普通文件夹上。

**沙箱本身没放松**，仍是 `workspace-write`。
所有放权参数都会原样出现在返回的 `command` 和 `permissionNote` 里——
不藏在代码里替用户做决定。

---

## 14. 「成没成」看产物存不存在，不看退出码

**决定**：`DispatchReport.outputExists` 才是判据。

**理由**：agent 可以退出码 0 但什么都没写（想岔了、觉得不需要改、写到别的地方去了）。
拿退出码当成功标志会让界面显示「已完成」而右栏空空如也。

---

## 15. 接管控制台时只补空句柄

**决定**：`AttachConsole` 之后，只对 `GetStdHandle` 返回空/无效的槽位调 `SetStdHandle`。

**理由**：无条件把 stdout 指向 `CONOUT$` 会把重定向冲掉——
`redline formats > out.json` 得到**零字节文件、退出码却是 0**。
这是实测踩到的，比报错难查得多。

---

## 16. 推翻早期「不做独立 app」的结论

**原结论**（README 早期版本）：先证明内核能被真实宿主（OpenCodex）用起来，
独立 app 以后再说。

**推翻理由**：**寄生在别人的宿主里，永远拿不到「双击一个 zip 就打开」这个入口**，
而那正是 WinRAR 的全部护城河。要取代它就得有自己的 exe、文件关联和右键菜单。

**没有放弃的部分**：内核仍然宿主无关（`RedlineHost` 接口没动），
OpenCodex 那条路没断。

## 17. JSON 字段统一 camelCase

**决定**：所有对外序列化的结构体加 `#[serde(rename_all = "camelCase")]`。
例外是信封元字段 `ok` / `version` / `tool` / `action_id`。

**理由**：消费方是 TS 前端和 AI agent。之前混用过
（`permissionNote` 和 `permission_note` 同时存在），前端直接读到 `undefined`。

---

## 18. archive 快照最多铺 500 条，且如实标注截断

**决定**：`summary.truncated` 写明省了多少条 + 怎么拿完整清单。

**理由**：静默截断会被读成「已经全看过了」。
这条是通用纪律，不只针对 archive——**任何地方做了 top-N / 采样 / 不重试，都要说出来**。

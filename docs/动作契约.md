# 动作契约

> 这是**对外稳定接口**。改这里的任何东西都是破坏兼容，要么升 `version`，要么别改。
>
> 已声明界面（GUI / CLI）看到的是同一份契约，因为它们调的是同一个
> `redline_core` Action Registry。MCP 尚未实现，因此没有伪造 MCP 契约。

## 信封

成功和失败**同一个形状**，调用方只需判一个布尔：

```json
{
  "ok": true,
  "version": 1,
  "action_id": "document.inspect",
  "execution_id": "ap-123",
  "result": { "...": "动作 payload" }
}
```

```json
{
  "ok": false,
  "version": 1,
  "action_id": "document.inspect",
  "execution_id": "ap-123",
  "error": {
    "class": "input | refused | internal",
    "code": "file_not_found",
    "message": "文件不存在：C:\\a.docx",
    "details": { "path": "C:\\a.docx" }
  }
}
```

**JSON 字段一律 camelCase**（消费方是 TS 前端和 AI agent）。
例外：`ok` / `version` / `action_id` / `execution_id` 是信封元字段，后两个保持下划线不动。

## 退出码（CLI）

| 码 | 含义 | 脚本该怎么办 |
|---|---|---|
| `0` | 成功 | 继续 |
| `1` | 输入错误：文件不存在、格式不支持、patch 非法 | 改参数重试 |
| `2` | **安全拒绝**：核心主动拒绝执行 | **别重试，让人来看** |
| `3` | 内部错误：解析崩了、IO 失败 | 报 bug |
| `64` | 用法错误：argv 拼不成合法请求 | 看 `--help` |

`2` 单独占一个码是有意的。安全拒绝不是 bug，是核心在保护用户的文件；
自动重试只会让人以为「重试几次就好了」，而实际情况是他的 patch 写得不够精确。

## 全部动作

### `document.inspect` —— 解析成结构化快照（只读）

```jsonc
// params
{ "path": "方案.docx" }

// payload
{
  "shadow": {
    "schema": "redline.shadow-document",
    "schemaVersion": 1,
    "producer": "redline-core/0.1.0",
    "profile": "semantic",
    "granularity": "paragraph",
    "lossy": true,
    "sourceSha256": "f500..."
  },
  "format": "docx",
  "source": { "path": "C:\\...\\方案.docx", "extension": "docx", "bytes": 32435, "sha256": "f500..." },
  "summary": { "paragraphs": 133, "tables": 2, "images": 0, "trackedInsertions": 0, "trackedDeletions": 0 },
  "units": [ {
    "id": "paragraph:1", "kind": "paragraph", "label": "段落 1",
    "text": "洪山区2026年…", "textSha256": "ab12...", "note": "可选"
  } ]
}
```

**`units[].id` 是整个系统的锚点**，标注、diff、agent 工单全靠它对齐。格式各自的 id 规则：

| 格式 | unit id | summary 字段 |
|---|---|---|
| docx | `paragraph:N` | paragraphs / tables / images / trackedInsertions / trackedDeletions |
| xlsx | `sheet:N` | sheets |
| pptx-outline | `slide:N` | slides |
| pdf | `page:N` | pages / pagesWithText / **needsOcr** |
| text / html | `document:1` | lines / chars |
| archive | `entry:N` | entries / directories / uncompressedBytes / truncated? |

- PDF 抽不出文字是**常态**（扫描件），不是错误。那一页的 `note` 会写明需要 OCR，
  `summary.needsOcr` 给出总数。**别假装有文本层。**
- archive 的 units 最多铺 500 条，超出会在 `summary.truncated` 里写明省了多少条。
  静默截断会被读成「已经全看过了」。
- `shadow.sourceSha256` 必须与 `source.sha256` 相同；它表示这份投影只对这一版原件有效。
- `units[].textSha256` 用于检测段落/页/工作表内容是否已经漂移，不能替代原件 sha256。
- ShadowDoc 是传统文件与 AI 之间的映射层，不是新的权威文件格式，见
  `docs/影文档协议.md`。

### `document.verify` —— 能不能被解析（只读）

params 同 inspect。payload 是 inspect 的精简版：`{ file, format, summary, units: <数量> }`。

### `document.diff` —— 结构化差异（只读）

```jsonc
// params
{ "before": "原件.docx", "after": "改后.docx" }

// payload
{
  "format": "docx",
  "before": { /* SourceInfo */ }, "after": { /* SourceInfo */ },
  "summary": { "totalUnits": 133, "changedUnits": 1, "unchangedUnits": 132 },
  "changes": [ { "id": "paragraph:2", "label": "段落 2", "before": "旧", "after": "新", "kind": "modified" } ]
}
```

`kind` ∈ `added` / `removed` / `modified`。
按 unit id 对齐、**数值排序**（`paragraph:2` 排在 `paragraph:10` 前面）。
跨格式对比会被拒绝（`format_mismatch`）。

### `document.formats` —— 格式注册表全文（只读）

无参数。渲染层靠这个动作对齐，`scripts/check-format-parity.mjs` 也读它。

```jsonc
{
  "formats": [ {
    "id": "docx", "label": "Word 文档", "extensions": ["docx"], "viewer": "DocxViewer", "tier": "free",
    "caps": { "inspect": true, "diff": true, "apply": true, "annotate": true, "extract": "none" }
  } ],
  "refused": [ { "extension": "doc", "reason": "旧版 .doc 是二进制格式：…" } ],
  "fallback": { "id": "unsupported", "...": "…" }
}
```

`caps.extract` ∈ `none` / `native`（纯 Rust zip）/ `external_7z`（需外部解包器，**还没接**）。

### `document.apply-track-changes` —— 唯一写文件的动作

```jsonc
// params
{
  "input": "方案.docx",
  "output": "待审.docx",          // 必须 ≠ input
  "author": "Codex",              // 可选，默认 "AI Redline"
  "force": false,                 // 可选，允许覆盖已存在的**输出副本**
  "patch": {
    "version": 1,
    "action_id": "document.apply-track-changes",   // 可选，给了就必须对
    "expected_input_sha256": "f500…",              // 可选但强烈建议：这是状态版本号
    "changes": [
      { "op": "replace_text", "old": "项目申报表", "new": "项目申报表（修订）", "reason": "可选" }
    ]
  }
}

// payload（同时也是审计记录）
{
  "input":  { "path": "…\\方案.docx", "sha256": "f500…" },
  "output": { "path": "…\\待审.docx", "sha256": "d4ce…" },
  "author": "Codex",
  "createdAt": "2026-07-30T17:45:58Z",
  "applied": [ { "index": 0, "op": "replace_text", "old": "…", "new": "…", "reason": null, "revisionId": 1 } ],
  "rollback": "删除输出文件即可回到原件；原输入文件未被修改。"
}
```

**只支持 `.docx`**：只有 Word 有原生 Track Changes 能承载修订痕迹。
pptx/xlsx/pdf 没有对应机制，与其自己发明一套不如不做。

`op` 目前只有 `replace_text`，且 `old` 必须在**一个** Word 文本节点中唯一出现。

### `archive.list` / `archive.extract`

```jsonc
// archive.list  params: { "path": "包.zip" }
{ "count": 16, "entries": [ { "path": "word/document.xml", "bytes": 121, "compressed": 44, "isDir": false, "format": "text" } ] }

// archive.extract  params: { "path": "包.zip", "dest": "./解出", "overwrite": false }
{ "written": 16, "files": ["C:\\…\\解出\\[Content_Types].xml", "…"] }
```

`entries[].format` 是按包内文件名判定的 Redline 格式 id ——「点进压缩包直接看里面的 docx」靠它。

**解包分两趟**：先把全部条目路径和覆盖冲突验一遍，一条不合格就整包拒绝，**零字节残留**。

### `agent.catalog` —— 有哪些 AI，装没装（只读）

```jsonc
{ "agents": [ {
  "id": "codex", "label": "Codex CLI", "program": "codex",
  "args": ["exec", "--sandbox", "workspace-write", "--skip-git-repo-check", "-"],
  "permissionNote": "workspace-write：允许在工作目录内改文件…",
  "installed": true,
  "resolvedPath": "C:\\Users\\…\\npm\\codex.cmd"
} ] }
```

`installed` 走 PATH 解析（Windows 按 PATHEXT 试后缀）。界面要能**提前**告诉用户「codex 没装」，
而不是等派发失败再报错。

### `agent.dispatch` —— 把标注派给 AI

```jsonc
// params
{
  "agent": "codex",
  "source": "方案.docx",
  "expectedSourceSha256": "f500...", // 可选但强烈建议；旧影文档不能派给已变化的原件
  "output": "改后.docx",          // 必须 ≠ source
  "annotations": [ { "unitId": "paragraph:2", "note": "改得更正式" } ],
  "instruction": "整体语气正式",   // 可选
  "cwd": null,                    // 可选，默认源文件所在目录
  "timeoutSecs": 600,             // 可选，0 = 默认 600
  "dryRun": false                 // 可选，只返回将要执行的命令和提示词
}

// payload
{
  "agent": "codex", "label": "Codex CLI",
  "command": ["codex", "exec", "--sandbox", "workspace-write", "--skip-git-repo-check", "-", "<提示词经 stdin 传入>"],
  "permissionNote": "…", "cwd": "…", "prompt": "<完整工单>",
  "source": "…", "output": "…",
  "exitCode": 0, "timedOut": false, "durationMs": 61521,
  "stdoutTail": "…", "stderrTail": "…",
  "outputExists": true
}
```

三条不可协商：

1. **`annotations` 只要给 `{unitId, note}`**，unit 正文由核心从快照补（`unitText` 也可显式给）。
   界面不重复读文档——否则「AI 看到的」和「人看到的」是两次独立解析的结果，迟早对不上。
2. **`command` 和 `permissionNote` 原样回传**，包括所有放权参数。不藏在代码里替用户做决定。
3. **「成没成」看 `outputExists`，不看 `exitCode`。** agent 可以退出码 0 但什么都没写。
4. 给了 `expectedSourceSha256` 后，派发瞬间源文件哈希不一致会以 `stale_shadow`
   安全拒绝；界面必须重新 inspect，不能自动拿新文件继续套旧标注。

`dryRun` 时 `exitCode` / `durationMs` / `stdoutTail` / `stderrTail` 全是 `null`。

## 错误码表

| code | class | 出现在 |
|---|---|---|
| `file_not_found` | input | 所有吃路径的动作 |
| `unsupported_format` | input | inspect / archive |
| `format_not_inspectable` | input | inspect（图片这类只能看不能解析） |
| `legacy_binary_format` | **refused** | inspect（.doc/.xls/.ppt） |
| `format_mismatch` | input | diff（跨格式） |
| `missing_ooxml_part` | input | OOXML 缺件 |
| `bad_archive` / `bad_json` | input | zip / JSON 解析失败 |
| `bad_xml` / `bad_xml_attribute` / `bad_encoding` / `zip_write` | internal | 解析或写盘崩了 |
| `not_an_archive` | input | archive.* 用在非压缩包上 |
| `extract_backend_missing` | input | rar/7z（后端还没接） |
| `unsafe_archive_path` | **refused** | zip-slip |
| `would_overwrite` | **refused** | 解包目标已存在 |
| `apply_format_unsupported` | input | apply 用在非 docx 上 |
| `bad_patch` | input | patch 结构非法 |
| `output_would_overwrite_input` | **refused** | 输出 = 输入 |
| `output_exists` | **refused** | 输出已存在且没 `--force` |
| `stale_patch` | **refused** | `expected_input_sha256` 对不上 |
| `stale_shadow` | **refused** | agent.dispatch 的源文件与预览/标注时哈希不一致 |
| `ambiguous_replacement` | **refused** | 替换点命中 0 或 ≥2 次 |
| `multi_text_run` | **refused** | 命中的 run 含多个文本节点 |
| `unknown_action` / `missing_param` / `bad_annotations` | input | dispatch 层参数校验 |
| `unknown_agent` / `agent_not_installed` | input | agent.dispatch |
| `agent_spawn_failed` / `agent_wait_failed` | internal | 子进程管理 |
| `inspect_not_wired` | internal | 注册表声明了 inspect 但核心没接实现（是 bug） |

## 计划中的动作（版本图 / 无限画布）

README 的「无限修改模式」需要把「一次回合」升级成**版本图**：每个版本是不可变快照，
每条连线是一次可审计的 AI 动作。这套东西**同样只能在核心实现一次**，
GUI 的画布、CLI 和 MCP 调的是同一批动作。

草案（尚未实现，改动前先在 `docs/决策记录.md` 里记一笔）：

| Action ID | 干什么 |
|---|---|
| `version.create` | 把一个文件登记成版本节点：内容哈希、父版本、创建时间、分支名 |
| `version.list` | 拉出整张版本图（节点 + 连线），供画布渲染 |
| `version.get` | 单个版本节点详情：路径、哈希、产生它的那次 AI 动作 |
| `version.branch` | 从任一历史版本开新分支（**不是回滚覆盖**，旧版本全部保留） |
| `version.adopt` | 用户最终选定某个版本：导出 / 另存 / 替换（替换要显式确认） |

设计约束（从现有铁律推出来的，别推翻）：

- 版本节点**不可变**。「继续改」永远是基于某个明确版本**生成新版本**，不是原地改。
- 每条连线要能完整重放：父版本哈希、标注、整体要求、agent + 模型 + 权限说明、
  输出文件、运行状态、与父版本的差异、时间戳。这既是画布数据也是企业审计凭证。
- 源文件不被静默覆盖。只有 `version.adopt` 且用户显式选「替换」才会动它。

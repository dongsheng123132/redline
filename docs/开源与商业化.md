# 开源与商业化

> 这份文档把[商业模型](./商业模型.md)里的原则落实为仓库、许可证和收费边界。
> 它不是法律意见；正式发布前需要对依赖许可证、商标和隐私条款做专业核验。

## 1. 结论

**开源产品层，收费服务层；免费的是用户控制权，收费的是持续发生的云成本、托管便利和企业责任。**

叠象不靠隐藏桌面代码挣钱。它要靠开源获得信任、格式生态、Agent 集成和事实协议地位，
再从官方云服务、团队托管和企业控制面获得收入。

## 2. 为什么核心和桌面端都开源

1. 文件工具接触合同、设计稿和私有资料，可审计比「相信我们」更重要；
2. Claude/Codex 等 Agent 更愿意调用稳定、公开、可验证的动作协议；
3. 长尾格式不可能只靠内部团队维护，需要社区贡献查看器、解析器和测试样本；
4. 桌面端闭源阻止不了重写，却会削弱「永远干净、源文件不覆盖」的可信度；
5. 付费 AI 的密钥、配额、成本控制和企业策略都在服务端，fork 不能凭空获得。

## 3. 开源与闭源边界

| 组件 | 许可证/状态 | 理由 |
|---|---|---|
| `crates/redline-core` | Apache-2.0 | Action、格式、安全和版本协议的事实标准候选 |
| `crates/redline-cli` | Apache-2.0 | 让脚本、自动化和测试不依赖 GUI |
| `crates/redline-mcp` | Apache-2.0（计划） | 让 Claude/Codex/其他 Agent 放心接入 |
| `packages/redline-core` | Apache-2.0 | 查看器和标注层需要社区扩格式 |
| `apps/redline-desktop` | Apache-2.0 | 可审计、可自建、建立用户信任 |
| ShadowDoc Schema、验证器和 conformance suite | Apache-2.0 | 任何开源或商业实现都能免费验证互操作 |
| ShadowDoc 规范正文 | 孵化期；正式发布前评审 Community-Spec-1.0 | 规范需要适合独立实现的 IPR 边界 |
| 云 Agent 客户端适配器 | Apache-2.0 | 请求格式公开，方便替换服务商 |
| 叠象官方云网关、计费、风控 | 私有仓 | 包含密钥、成本控制、反滥用和商业规则 |
| 企业策略、审计汇聚、SSO 控制面 | 私有仓 | 企业为托管、责任与持续运维付费 |
| 品牌、Logo、签名证书、官方域名 | 不随 Apache-2.0 授权 | 代码可 fork，不代表可冒充官方发行版 |

Apache-2.0 允许商业使用、修改和分发，同时带专利授权条款；它不自动授予项目商标使用权。
发布前应补 `TRADEMARKS.md`，明确社区 fork 可描述“基于 Redline”，但不能使用叠象/Stelora
名称、Logo、签名和官方更新地址冒充官方版本。

ShadowDoc 如何从产品内部模型成为独立开放规范，见
[ShadowDoc 开源规范与生态计划](./ShadowDoc开源规范与生态计划.md)。
规范、软件、教程和样例数据不一定适用同一种许可证；正式引入规范专用许可证前必须做
知识产权与专利条款核验，不能把“代码已是 Apache-2.0”当成完整标准治理。

## 4. 免费承诺

官方发行版和开源版都必须永久免费提供：

- 本地打开、预览和格式识别；
- 本地解压与安全检查；
- 标注、导出机器可读工单；
- 本地版本图、差异和另存为；
- 自带 Claude/Codex/其他 key 或本地模型；
- CLI、MCP 和 Action 协议；
- 不登录即可完成的本地工作流。

不能用次数、水印、弹窗或故意降速限制这些能力。尤其不能把某种常用格式突然移到付费层，
那会破坏「万能打开器」的品类承诺。

## 5. 收费产品

### 5.1 一键云 AI

面向不想安装 CLI、购买模型 key 或配置环境的个人用户：

- 一次登录即可选择官方托管的模型；
- 按任务展示预计价格区间，完成后展示真实用量；
- 余额、超时、模型拒绝、文件过大分别报错；
- 收费由「模型成本 + 转换/OCR/存储成本 + 服务费」组成；
- 允许用户随时改回自带 key，不锁文件和版本历史。

初期适合按量充值，不急着做月费。只有用户出现稳定月度复购后，再测试订阅：

| 套餐假设 | 可以包含 | 不能伪装成权益的东西 |
|---|---|---|
| 按量 | 云模型调用、云转换、OCR、临时运行环境 | 本地打开、标注、解压 |
| Plus（月费实验） | 月度云额度、跨设备版本同步、优先队列、较长任务 | 本地版本图、MCP、自带 key |
| 团队 | 共享项目、权限、集中余额、团队模板 | 读取用户本地文件的默认权限 |

### 5.2 企业

企业付费购买的不是一个特殊查看器，而是：

- 私有部署和模型出口控制；
- 组织策略：允许哪些 Agent、格式、目录和动作；
- SSO、角色、审批和预算；
- 审计日志汇聚、保留、检索和导出；
- 受支持的离线转换组件；
- SLA、漏洞响应、版本支持和部署服务。

企业客户端仍可使用开源桌面端；企业控制面、托管与支持按年签约。

### 5.3 可选服务收入

- 特定行业格式适配和验收服务；
- 私有插件开发；
- 批量迁移、流程集成和培训；
- 官方认证的格式/Agent 插件市场抽成。

插件市场不能以「付费才允许打开普通文件」为基础，只能为专业适配、云算力或持续服务收费。

## 6. 开源后为什么仍会有人付费

| 用户可以自己做 | 官方服务替用户承担 |
|---|---|
| 编译客户端 | 签名安装包、自动更新、杀软信誉和回滚 |
| 配置自己的模型 | 统一账号、余额、模型选择、失败重试和账单 |
| 自建 MCP/云网关 | 全球/国内可用性、限流、风控和监控 |
| 保存本地历史 | 跨设备同步、分享、备份和恢复 |
| 自行审计日志 | 组织策略、合规留存、SSO、报表和 SLA |
| fork 品牌 | 官方品牌、下载入口、社区、兼容认证和支持 |

官方发行版必须比 fork 更省心，而不是靠人为制造兼容障碍。

## 7. 单位经济纪律

云 AI 不能把充值额全部当收入。每个任务至少记录：

- 模型输入/输出 token 和真实采购成本；
- OCR、转换、沙箱、带宽、存储和退款成本；
- 支付渠道费；
- 服务毛利；
- 用户是否因失败重试而重复扣费。

原则：

1. 模型调用失败且无有效产物，不收模型服务费；
2. 估价与结算差异过大时给用户确认，而不是事后惊吓；
3. 初期追求任务成功率和复购，不用高毛利掩盖坏体验；
4. 企业合同必须覆盖支持、私有部署和长期维护的人力。

## 8. 商业化阶段门槛

| 阶段 | 先证明什么 | 进入下一阶段的门槛 |
|---|---|---|
| 0 工具成立 | 用户会安装并反复用它打开文件 | 500 台真实安装；第 4 周有效留存 ≥20%；源文件事故为 0 |
| 1 Agent 成立 | 标注能提高修改成功率 | 200 次真实派发；产物成功率 ≥80%；有重复使用 |
| 2 云 AI 成立 | 用户愿为免配置和稳定运行付费 | 100 名试用者中出现 ≥10 名真实付费，且有复购 |
| 3 团队成立 | 版本共享与集中预算有价值 | 3 个持续使用的设计伙伴团队 |
| 4 企业成立 | 审计、策略和私有部署能签合同 | 至少 2 个付费试点，再投入完整控制面 |

数字是决策门槛，不是对外宣传。未达到门槛时先修产品，不提前建设下一层组织。

## 9. 贡献与供应链计划

公开发布前补齐：

- `CONTRIBUTING.md`：新增格式、Action、Viewer 和测试样本的流程；
- DCO 签署或等价贡献声明，保持版权来源清晰；
- ShadowDoc RFC、实现报告和 conformance fixture 模板；
- `SECURITY.md`：私密报告 zip-slip、任意文件写入等漏洞；
- `TRADEMARKS.md`：代码许可和品牌许可分离；
- 自动生成 SBOM 与第三方许可证清单；
- Release 二进制、安装包、更新清单都签名并发布校验值；
- 对外部转换器采用进程外调用，并把许可证与下载来源写入清单。

不接受会把项目整体拖入 GPL/AGPL 或 unRAR 限制的依赖，除非经过明确的架构与法律评审。

## 10. 最需要防的风险

| 风险 | 防线 |
|---|---|
| 大模型平台覆盖主流文档预览和修改 | 做系统入口、长尾格式、模型中立和不可变审计 |
| 格式覆盖变成无底洞 | 分级支持、黄金测试语料、插件机制、按真实打开失败排序 |
| fork 分流用户 | 官方签名、更新、云服务、兼容认证和品牌；不设人为锁 |
| 云 AI 毛利太薄 | 透明服务费、批量采购、多模型路由、企业收入 |
| 用户不愿上传文件 | 本地优先、自带 key、私有部署、任务级披露 |
| 免费用户多但不付费 | 先验证重复使用，再测试云便利和同步，不靠锁免费功能 |
